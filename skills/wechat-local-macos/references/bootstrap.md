# 可选：通过临时调试副本取得本机数据库密钥

仅在读取当前用户自有微信账号、本机已有密钥无法解开选定数据库时使用。已有可用密钥直接复用，正常读取与语音转写均不需要此流程。先区分权限错误、账号或数据库路径选错、版本不兼容和真正的密钥不匹配。

## 授权与适用边界

- 开始前须有用户对本轮具体操作的明确授权：正常退出原版微信、复制到新的私有目录、仅对副本进行 ad-hoc 签名、通过 LLDB 启动副本，必要时在副本中完成手机确认登录，以及结束时退出副本并恢复原版启动。同一会话已经覆盖这些操作的授权继续有效，不重复询问。
- `--acknowledge-debug-copy` 是脚本防误运行参数，本身不证明用户已经授权。只授权读取聊天不等于授权改签名或调试启动。
- 不修改 `/Applications/WeChat.app` 的任何文件或签名；不替换安装版，不禁用 SIP，不使用 `sudo`，不获取其他用户账号数据。只管理本流程启动的进程，不按进程名批量结束微信。
- 已验证条件为原生 Apple Silicon / arm64、macOS 27.0.1、微信 4.1.15（270115）。这是一次验证记录，并非其他版本的兼容承诺。Rosetta、Intel 和新版客户端须重新核对调用约定及数据库格式，不能直接扩大扫描、猜偏移或更改系统保护来尝试适配。
- 此实现观察启动中的 `CCKeyDerivationPBKDF` 调用；使用 arm64 参数寄存器，按选定数据库第一页的 salt 筛选，再用 HMAC 验证。它假定相应 SQLCipher 页面布局（4096 字节页及 SHA-512 校验等）。成功条件是数据库验证通过，不是仅捕获到一段字节或命中断点。

## 准备

1. 正常运行并登录原版微信，确认选定账号的数据库已生成；记录原版可执行文件、版本和签名验证结果。让用户正常退出微信，确认不存在仍在运行的原版实例；脚本发现已有实例时应停止，不自行强制结束。
2. 以当前登录用户运行，检查系统 `/usr/bin/lldb` 及其 Python 绑定可用；脚本使用 `/usr/bin/python3` 与 `lldb -P` 返回的绑定路径。缺少开发工具时说明依赖，不绕过系统权限。
3. 明确选择一个账号的 `db_storage`。多账号时要求选定账号，不逐个读取内容来猜测。默认账号发现只能在恰好一个候选时采用。
4. 新建独立的私有状态目录（0700），最终密钥文件权限为 0600。已有 `keys.json` 或前次临时副本时拒绝覆盖；需要重试则创建新目录，先保留旧密钥。运行中阶段结果也不能覆盖此前已存在的最终文件。

下列命令只展示接口。将三个占位路径替换为本机已核对的路径，在读取本说明且满足授权后执行；不要把密钥写入命令行：

```bash
python3 /absolute/path/to/wechat-local-macos/scripts/bootstrap_keys.py \
  --app /Applications/WeChat.app \
  --db-root /absolute/path/to/selected-account/db_storage \
  --state-dir /absolute/path/to/new-private-run \
  --timeout 300 \
  --acknowledge-debug-copy
```

`scripts/bootstrap_keys.py` 负责复制、仅签副本、调用捕获及恢复；`scripts/capture_keys.py` 负责启动一个明确指定的副本进程并验证密钥。不要跳过包装脚本直接启动捕获器来绕过恢复流程。查看结果时只报告验证数据库数量、文件权限与状态；不打印、链接、上传或写入普通日志的密钥内容。

## Full Disk Access 与登录

macOS 的 Full Disk Access（完全磁盘访问权限，FDA）是独立故障来源：

- 执行读取的宿主（例如 Codex 或终端）需要能够读取微信容器。宿主没有权限时，数据库枚举和读取可能表现为 `Operation not permitted`。这是权限问题，不能归因为密钥错误。
- 临时改签名副本与原版、宿主分别受 TCC 管理。即使宿主已获 FDA，副本仍可能在登录后打不开自己的容器、报告访问失败或始终不产生可验证调用。用户需要在“系统设置 → 隐私与安全性 → 完全磁盘访问权限”中为临时副本独立授权，必要时重新启动该副本。先确认授权，不能把零条密钥直接解释为加密方案已变化。
- 用户可能需要在副本窗口选择进入微信并在手机确认登录。只在本机界面完成；不读取验证码、截取登录凭据或代发消息。重新启动也必须仍属于已授权操作，并受同一有界运行及清理约束。

不要自动执行会影响其他应用授权的全局 TCC 重置。FDA 不等于 LLDB 调试授权；系统拒绝调试启动时保留错误并停止，不能因此禁用 SIP 或改签原版。

## 运行、超时与结果判断

- 单轮捕获等待上限为 300 秒。捕获器内部上限不能替代包装器的有界等待：复制、签名、启动、捕获子进程及清理均须有可执行的超时和退出路径；任何阶段停滞时结束本轮，不无限等待用户操作或后台子进程。
- 只对指定账号数据库的 salt 进行验证；只把验证通过的密钥写入私有状态目录。未知或不匹配参数直接忽略，不保存任意进程内存、完整调用参数或账号凭据。
- 记录已验证数量和目标数据库总数。部分成功必须标明缺失项；返回码为零或最终文件存在都不能代替完整性判断。超时后仍可保留已验证的部分结果，使用时仅覆盖实际通过验证的数据库。
- 捕获后重新用只读方式验证所需数据库。FDA、数据库路径、文件格式或版本不符应分别报告；不要删除旧密钥后盲目重试。

## 无论成功、失败或超时，都完成恢复

1. 结束捕获子进程及本轮明确启动的临时微信进程；等待退出，并核对错误结果。记录进程 PID 和可执行路径，只清理本轮拥有的进程。不能只调用 `Kill()` 就宣称已退出，也不能杀掉后来由用户启动的原版。
2. 对安装版重新执行 `codesign --verify --deep --strict`，并核对保存的签名标识；仅比较 `codesign -dvv` 输出不足以确认资源未被改动。异常时停止自动恢复步骤并明确报告，不重新签名原版来掩盖差异。
3. 确认副本进程已退出后，撤销临时副本的 LaunchServices 注册，将临时 `.app` 改为不可启动的 `.disabled` 路径。若退出或禁用失败，报告残留路径和具体恢复步骤，不继续启动第二个微信实例。
4. 使用已经核对的安装版可执行路径恢复原版启动，核对实际运行进程的可执行路径及存活状态；必要时由用户确认原版窗口和登录状态。仅有 `original_launch_requested` 或一次 `Popen` 成功不表示恢复完成。
5. 请用户在“系统设置 → 隐私与安全性 → 完全磁盘访问权限”关闭或移除临时微信副本条目，并核对其已关闭。临时 bundle 被改名、撤销注册或进程退出均不会自动撤销 FDA。宿主的 FDA 是否保留按用户已有偏好处理，不随意改变。
6. 分别报告“捕获结果”“临时进程退出”“临时 bundle 禁用”“原版签名核验”“原版恢复启动”“临时副本 FDA 撤销”的实际状态。任一恢复步骤未完成时明确保留为待处理，不声称已经全部恢复。不要为重试覆盖已有密钥。

通常不再需要临时副本，但在用户确认原版恢复前保留可定位的私有运行记录。只有不含密钥、账号目录或聊天内容的通用程序和脱敏诊断可以纳入 skill；所有实际密钥、数据库、音频和用户记录留在用户本机的私有数据目录。
