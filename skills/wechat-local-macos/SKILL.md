# 微信本地消息读取

把用户选定会话的消息和本地语音读出来，保留时间、消息 ID、账号发送人及内容缺口。正常路径使用已有密钥和 SQLCipher 只读连接，不启动调试副本、不改变微信。

## 先确定范围与运行环境

- 复用当前对话已有的账号选择、密钥路径与授权，不因应用此 skill 再要求重复确认。没有明确目标联系人或时间范围时，先解析用户给出的联系人；有重名或多个本地账号再澄清，不任选第一项。
- 先读取本机私有配置 `~/Library/Application Support/WeChatLocal/config.json`（如存在），使用其中的 `key_file`、`db_root`、`state_root` 和可选转写路径。配置不是 skill 的一部分，不纳入 Git。
- 无现成配置时，运行 `python3 scripts/doctor.py`，再按 [环境与读取](references/reading.md) 配置。区分 Full Disk Access、无本地数据、账号选择与密钥不匹配；诊断不到数据库不能证明密钥失效。
- 已验证环境是 Apple Silicon macOS、微信 4.1.15（270115）。数据库布局、调试调用和语音解码对其他版本的兼容性需要实测，不笼统承诺支持所有微信版本或 Windows。

文档中的 `scripts/...` 相对于此 skill 目录。实际执行时使用脚本的绝对路径，或先明确切换到此目录；不依赖聊天工作区恰好在 skill 中。

## 常规读取

1. 使用 `scripts/wechat_db.py --key-file <private-key-file> [--db-root <selected-db-root>] verify` 确认所需数据库可读。密钥只从私有文件进入，不放入命令行、日志或对话。
2. 用同一命令前缀执行 `resolve '<联系人昵称/备注/用户名>'`。只有唯一精确匹配时继续；重名时用明确 username 选择，保留用户选择。
3. 少量查看用 `read --chat-id <id> --limit 20`；完整导出用 `scripts/export_messages.py`，接口见 [环境与读取](references/reading.md)。直接读取活动数据库，让 SQLite 正确处理已提交的 WAL；单独复制 `.db` 会漏掉未 checkpoint 的消息。
4. 导出标准文字与引用回复中本人写的文字；不把被引用原文、转发材料或媒体标题当成本人表达。其他消息保留类型和占位，不声称已解析图片、视频、通话或表情语义。
5. `--self-id` 只在用户身份从已知本人消息得到确认时提供；否则保持 `from_self=null`，保留 sender_id，不凭昵称、目录名或文字内容猜‘我/她’。

首次没有可用密钥时才读取 [可选密钥引导](references/bootstrap.md)。它涉及临时副本签名和调试启动，需要当前会话已经授权这些具体改动；只授权读取不能自动扩大成对应用改签名的授权。满足已有授权后直接执行，不重复询问。

## 语音与增量

- 用户要求读语音或完整消息时，使用 `scripts/voice_export.py`；只有非空音频 blob 才算可用，空索引、冲突和不存在的缓存分别保留状态。详见 [语音提取与本地转写](references/voice.md)。
- 用户要求转写时，先复用已有本机环境和模型；`scripts/transcribe_local.py` 只接受已存在的本地模型，按配置与音频哈希缓存、断点续跑。不要为仅仅读文字安装 ASR 环境，也不要自动上传语音或启用第三方识别。
- 账号发送人与实际发声者不是同一概念。借账号录音、亲属发声、背景广播和不稳定转写必须谨慎归属。分析基于转写时，不能宣称听过语气。
- 缺失音频不补写；用户决定通过官方迁移补齐后，重新提取并续跑。不要无限等待补齐或自行开启监控。
- 用户明确需要增量读取时，按 [环境与读取](references/reading.md) 使用 `init/check/ack`。建立基线后旧记录不能作为新消息；处理成功后才 ack，按数据库名与 local_id 去重。

## 保存与交付

运行目录放在 Git 和微信数据库目录外，例如 `~/Library/Application Support/WeChatLocal/`。目录 0700、文件 0600。Git 只包含通用脚本、说明和合成测试；不能包含密钥、配置、真实账号、数据库、录音、聊天导出或个人画像。

报告实际读取的范围、成功条数、缺失/冲突/转写存疑数量，附本机结果链接。不要把‘有消息记录’说成‘已取得音频’，或把机器结果说成人工确认。读取行为本身不授权发送消息、自动回复、客户营销、长期监控或额外建立人物画像。
